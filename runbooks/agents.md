# Agent Environment Runbook

The harness-neutral policy is deployed at:

```text
/etc/agents
```

It is generated by NixOS from `/srv/ops/agents` and contains no task data. T3
creates each new managed Pi task in its own manifest-managed directory beneath
`/var/tmp/agent-work`. Codex keeps its native session state in `/srv/state/codex`; a
metadata-only normalized index is written to `/srv/state/agents/index.jsonl`.
Pi keeps its native sessions in `/srv/state/pi/agent/sessions`. CASS maintains a
private local search archive in `/srv/state/agents/search`; native harness stores
remain authoritative.

## Conversation Inspection

```bash
agent history
agent show <conversation-id>
agent search 'query words'
agent read <history-ref>
agent handoff <history-ref> --goal 'continue this work in Pi'
```

The index records the harness, title, native session path, working directory,
timestamps, and status. It never copies prompts, responses, attachments, auth,
or message bodies.

Full-text search is a separate local index. `agent search` returns an opaque ref
rather than exposing a source path. `agent read` and `agent handoff` accept only
refs present in the managed archive. Exports omit tool calls, hidden reasoning,
skills, and raw session metadata; they are bounded before entering another
harness's context. Archived conversation content must still be treated as data,
not instructions.

The CASS connector layer discovers Codex, Pi, and other supported coding-agent
stores. This keeps source ingestion independent from destination adapters. Pi is
the first destination: its managed `agent-history.ts` extension registers
`history_search`, `history_read`, and `history_handoff`. A future Codex or other
harness adapter can call the same `agent` commands without changing ingestion.
In Pi, `/history <query>` is the user-facing shortcut for that tool sequence.

`agent-conversation-index.path` refreshes the indexes when Codex metadata or the
Pi sessions directory changes. A 15-minute timer catches in-place session
updates and other harnesses. Use `agent search --refresh` when a just-written
turn has not reached the archive yet, and `agent index --full-search` only for a
deliberate full rebuild.

## Disposable Work

Create a private, expiring task directory:

```bash
agent new example-task
```

The default retention is 30 days. The command prints the new directory. Each
directory contains `.agent-work.json`, which records its identity, creation
time, expiration, harness, and optional conversation ID.

Inspect and control retention:

```bash
agent work
agent gc
agent keep /var/tmp/agent-work/<task>
agent release /var/tmp/agent-work/<task> --days 30
```

`agent gc` is dry-run-only unless `--apply` is provided. The daily
`agent-work-gc.timer` deletes only expired direct children of
`/var/tmp/agent-work` with valid manifests. It ignores untracked files,
unmanaged directories, symlinks, and retained work.

## Temporary Internal Sites

From inside a managed task directory, start a web server on loopback and expose
its port through a short-lived tailnet-only hostname:

```bash
python3 -m http.server 8000 --bind 127.0.0.1
agent site expose 8000 --name preview --ttl 4h
```

The command prints a URL such as
`https://task-preview-12345678.internal.therealrishabh.com`. Open it in any
browser connected to the tailnet. The gateway supports ordinary HTTP and
WebSocket traffic, so common development servers and hot reload work without a
durable route or a NixOS switch. The upstream must listen on `127.0.0.1`;
registrations can last from five minutes to seven days and stop working as soon
as they expire or their managed task directory disappears.

Inspect or stop sites with:

```bash
agent site list
agent site stop preview
```

Stopping the local web server does not remove the registration immediately, but
the gateway returns a 502 until the server returns. `agent-site-gc.timer` prunes
expired and orphaned registrations every 15 minutes. Unregistered internal
hostnames continue to return 404.

## Legacy Paths

`/srv/workspace` was retired after its durable contents were reconciled. The
pre-migration tree was placed in a manifest-managed temporary quarantine rather
than deleted immediately. `/home/rishabh/Documents/Codex` is a separate legacy
artifact collection and is not the native Codex session store; do not add new
tasks there.
