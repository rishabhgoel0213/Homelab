# Agent Environment Runbook

The harness-neutral policy is deployed at:

```text
/etc/agents
```

It is generated by NixOS from `/srv/ops/agents` and contains no project data.
Codex keeps its native session state in `/srv/state/codex`, and Pi keeps its
native sessions in `/srv/state/pi/agent/sessions`.

## Durable Project Work

Create and inspect projects with the harness-neutral project CLI:

```bash
projectctl create example-project
projectctl list
projectctl show example-project
```

Every top-level directory beneath `/home/rishabh/Projects` is immediately usable
as an implicit project. `projectctl create` or `projectctl init` adds a stable
`project.toml`, a standard content layout, and a project-owned Nix environment
without overwriting an existing `flake.nix`, `AGENTS.md`, or `.gitignore`.

Launch a harness or run another command in the project environment:

```bash
projectctl session example-project codex
projectctl session example-project pi
projectctl exec example-project -- pytest
projectctl shell example-project
```

The harness registry is Nix-managed and can gain future providers without
changing the project format. A project with `flake.nix` runs commands and
harnesses through its development shell by default; use `--direct` only when
the host environment is intentionally required.

## JupyterLab

Print a browser-ready link directly to a project:

```bash
projectctl jupyter example-project
```

For a Nix-backed project this also registers a project-specific Python kernel
whose process starts inside the project environment. `--no-kernel` prints the
link without touching Jupyter runtime state.

## Durable Destinations

- Infrastructure and this policy: `/srv/ops`.
- Software, forks, and research: `/home/rishabh/Projects`.
- Non-code user output: `/home/rishabh/Documents`.
- Service and native harness state: `/srv/state`.

See [Durable projects](projects.md) for the manifest contract and CLI surface.

## Legacy Paths

`/srv/workspace` was retired after its durable contents were reconciled.
`/home/rishabh/Documents/Codex` is a separate legacy artifact collection and is
not the native Codex session store; do not add new projects there.
